# ADR-0002. Сервис подбора водителей вынесен в отдельный контейнер

**Дата:** 2026-10-16
**Статус:** принято

## Контекст

Подбор водителя — самая нагруженная часть системы. В часы пик количество одновременных заказов достигает 10 000, и для каждого нужно найти ближайшего свободного водителя с учётом рейтинга, приоритета и радиуса поиска. Если эта логика будет внутри Backend API, она начнёт конкурировать за ресурсы с обработкой платежей, отзывов и других операций. Кроме того, алгоритм подбора требует частого чтения статусов водителей из БД, что создаёт дополнительную нагрузку.

## Рассмотренные варианты

1. **Оставить логику подбора внутри Backend API.** Проще, один контейнер, нет сетевых вызовов. Но при пиковой нагрузке весь API деградирует: запросы на оплату и отзывы будут ждать, пока освободятся потоки подбора.
2. **Вынести подбор в отдельный контейнер `matcher`.** Сложнее: появляется сетевой вызов, нужна синхронизация с БД. Но нагрузка изолирована, `matcher` можно масштабировать горизонтально независимо от API.

## Решение

Вариант 2. Отдельный контейнер `matcher` на Kotlin, который общается с Backend API по JSON/HTTPS и читает статусы водителей из основной БД. Публикует событие `DriverAssigned` в очередь.

## Последствия

**Плюсы:**
- `matcher` масштабируется независимо: в часы пик можно поднять 5 подов вместо 2.
- Падение `matcher` не роняет API: заказы можно создавать, оплата работает, только подбор временно недоступен.
- Алгоритм подбора можно менять, не трогая API.
- Нагрузка на БД распределяется: `matcher` читает только статусы водителей, API — всё остальное.

**Минусы:**
- Появляется сетевой вызов между API и `matcher` — добавляется точка отказа.
- Нужна синхронизация: `matcher` должен видеть актуальные статусы водителей.
- Усложняется развёртывание: отдельный под, отдельный CI/CD.
- Требуется контракт между API и `matcher` (OpenAPI или gRPC-схема).

**Что станет неверным, если решение пересмотреть:**
- C4 Container (`matcher` исчезнет с диаграммы).
- C4 Component (`MatchService` переедет внутрь Backend API).
- Диаграмма развёртывания (уйдёт под `matcher`).
- Диаграмма последовательности `main-flow.puml` (вызов `назначитьВодителя()` пойдёт не в `drv`, а внутрь `svc`).
