## ВИ-01. Заказать поездку (самый ценный для бизнеса)

**Актёры:** Клиент (первичный), Водитель, Платёжный шлюз, Картографический сервис
**Цель:** оформить заказ такси с расчётом стоимости и подбором водителя
**Предусловия:** клиент авторизован; указаны адрес подачи и адрес назначения; аккаунт не заблокирован
**Постусловия (успех):** создан заказ; назначен водитель; сумма зарезервирована на платёжном шлюзе; клиент уведомлён
**Постусловия (неуспех):** заказ не создан; резерв не удержан; состояние системы не изменилось
**Тип:** базовый
**Связи:** include ВИ-06 «Проверить статус клиента»; extend ВИ-07 «Рассчитать цену», ВИ-08 «Подобрать водителя»

### Основной сценарий

| # | Действие актёра | Отклик системы |
|---|---|---|
| 1 | Клиент указывает адрес подачи и адрес назначения | 2. Система запрашивает у картографического сервиса координаты и расстояние |
| | | 3. Система рассчитывает стоимость поездки с учётом тарифа и коэффициента спроса |
| 4 | Клиент подтверждает заказ | 5. Система проверяет статус клиента: нет долгов и блокировок |
| | | 6. Система подбирает свободного водителя в радиусе 5 км |
| | | 7. Система резервирует сумму на платёжном шлюзе |
| | | 8. Система уведомляет клиента: «Водитель назначен» |
| 9 | Клиент ожидает подачу автомобиля | 10. Система передаёт заказ водителю |

### Исключения

**И-1. Клиент отказался от заказа** (шаг 4)
Система не создаёт заказ и завершает сценарий.
Состояние системы не изменяется.

**И-2. Клиент заблокирован или имеет долг** (шаг 5)
Система показывает причину блокировки и предлагает обратиться в поддержку.
Заказ не создаётся. Возврат к шагу 1 либо завершение.

**И-3. Свободных водителей нет** (шаг 6)
Система расширяет радиус поиска до 10 км.
Если водителей нет и там — предлагает клиенту подождать или отменить заказ.
Если клиент ждёт — повтор поиска каждые 30 секунд.

**И-4. Водитель не принял заказ** (шаг 10)
Прошло 30 секунд — ответа нет.
Система блокирует водителя на 5 минут и ищет следующего.
Если все водители проигнорировали — возврат к И-3.

**И-5. Платёжный шлюз недоступен** (шаг 7)
Система отменяет заказ и уведомляет клиента о технической ошибке.
Резерв не удержан. Возврат к шагу 1.

### Примечания
Коэффициент спроса рассчитывается отдельным сервисом динамического ценообразования (см. доменную модель, часть 3).
При высоком спросе коэффициент может достигать ×2.0.

## ВИ-02. Подобрать водителя (самый рискованный в реализации)
**Актёры:** Водитель (первичный), Картографический сервис, Система заказов
**Цель:** найти ближайшего свободного водителя с учётом рейтинга, удалённости и загруженности
**Предусловия:** есть активный заказ; у водителя статус «свободен»; геолокация обновлена менее минуты назад
**Постусловия (успех):** водитель назначен; водитель снят со свободных; клиент уведомлён
**Постусловия (неуспех):** заказ остаётся без водителя; система возвращает ошибку «Нет доступных водителей»
**Тип:** базовый
**Связи:** extend ВИ-05 «Обновить геолокацию», ВИ-09 «Разрешить конфликт заказов»

### Основной сценарий
| # | Действие актёра | Отклик системы |
|---|---|---|
| | | 1. Система получает координаты клиента через картографический сервис |
| | | 2. Система формирует список водителей в радиусе 5 км |
| | | 3. Система фильтрует водителей со статусом «свободен» |
| | | 4. Система сортирует список по рейтингу и удалённости |
| | | 5. Система отправляет заказ первому водителю |
| 6 | Водитель принимает заказ | 7. Система фиксирует назначение и снимает водителя со свободных |
| | | 8. Система уведомляет клиента о назначении |

### Исключения
**И-1. Геолокация водителя устарела** (шаг 1)
Система запрашивает обновление координат.
Если водитель не отвечает — исключается из списка.
Возврат к шагу 2.

**И-2. Несколько заказов претендуют на одного водителя** (шаг 5)
Система применяет блокировку (mutex) на водителя.
Первый заказ получает водителя, второй — возвращается к шагу 2.
Водителю отправляется только одно предложение.

**И-3. Водитель не отвечает** (шаг 6)
Прошло 30 секунд — нет ответа.
Система снижает приоритет водителя на 10 минут и переходит к следующему.
Если список пуст — возврат к шагу 2 с расширенным радиусом.

**И-4. Водитель отказался** (шаг 6)
Водитель нажал «Отклонить».
Система понижает его приоритет в списке.
Переход к следующему водителю.

**И-5. Картографический сервис недоступен** (шаг 1)
API вернул таймаут.
Система использует кэшированные координаты.
Если кэша нет — сценарий завершается с ошибкой «Нет данных о местоположении».

### Примечания
Это самый рискованный сценарий из-за:
- гонок данных (несколько заказов на одного водителя);
- внешних API (картографический сервис);
- устаревших данных (геолокация);
- высокой нагрузки (пиковые часы).
Требуется распределённая блокировка (Redis, etcd) для синхронизации.
